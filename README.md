# dotfiles

Dotfiles monorepo built around GNU Stow. Supports Arch Linux and Ubuntu/Debian.

## Layout

- `modules/` contains installable packages in Stow layout
- `install/` contains bootstrap, wizard, and apply scripts
- `profiles/` contains example profiles you can adapt

## Quick start

```bash
./install/bootstrap.sh
```

Bootstrap installs `stow` if needed, saves your module choices, installs module packages from the OS-specific manifests (under `install/manifests/arch/` or `install/manifests/ubuntu/`), runs any post-install hooks, and links the selected modules into `$HOME`.

## Wallpaper overrides

The awesome module ships with a default wallpaper from the repo. To use a machine-specific wallpaper, set one in the wizard or add a symlink at:

```text
~/.config/awesome/wall.override
```

The config will prefer that file when it exists.

## Alacritty

The Alacritty module keeps two repo-managed themes:

- dark: `nightfox`
- light: `dawnfox`

Keybindings:

- `Ctrl+Shift+F10` toggles dark/light
- `Ctrl+Shift+F11` switches to dark
- `Ctrl+Shift+F12` switches to light
- `Ctrl+=` / `Ctrl++` increases font size
- `Ctrl+-` decreases font size
- `Ctrl+0` resets font size

Mouse behavior:

- selecting text copies it to the clipboard automatically
- right click pastes the clipboard

The font-size bindings are useful for temporary zooming, like screen sharing or presentations.

## Zsh

The zsh module manages:

- `~/.zshrc`
- `~/.zshenv`
- `~/.p10k.zsh`

On apply, the installer also bootstraps:

- `~/.oh-my-zsh`
- `powerlevel10k`
- `zsh-vi-mode`

The install flow does not change your login shell automatically.

## YubiKey

The YubiKey module manages safe config only:

- `~/.gnupg/common.conf`
- `~/.gnupg/gpg-agent.conf`
- `~/.gnupg/sshcontrol`
- helper scripts under `~/.local/bin/`

It does **not** store private keys, secret subkeys, stubs, trustdb data, or card state in the repo.

Included helpers:

- `yubikey-refresh` updates `gpg-agent` TTY state for pinentry
- `yubikey-ssh-enable` adds your GPG authentication subkey to `~/.gnupg/sshcontrol`
- `yubikey-ssh-pubkey` exports your SSH public key from GPG

The zsh module also refreshes `GPG_TTY` automatically in interactive shells so
git signing keeps working inside terminals and Zellij panes.

You will usually also want `pcscd` running so the card is visible to GnuPG. On Arch: `sudo systemctl enable --now pcscd.socket`. On Ubuntu: `sudo systemctl enable --now pcscd`.

### Reconnect handling (pcscd hotplug)

pcscd doesn't always notice a YubiKey that's been unplugged and reinserted,
and gpg-agent's `scdaemon` keeps a stale PC/SC session open to the old
reader, so `pinentry`/`gpg-agent` can't see the card again until you
manually run `sudo systemctl restart pcscd`. The `yubikey` module's install
hook (`install/hooks/yubikey.sh`) installs a udev rule + systemd service to
do this automatically:

- `/etc/udev/rules.d/99-yubikey-pcscd-reload.rules` — matches the YubiKey's
  USB vendor ID and asks systemd to start `yubikey-pcscd-reload.service`
  whenever the device is (re)plugged in.
- `/etc/systemd/system/yubikey-pcscd-reload.service` — a oneshot unit that
  runs `/usr/local/libexec/yubikey-pcscd-reload`
  (`install/resources/yubikey/yubikey-pcscd-reload`), which:
  1. Runs `udevadm settle` plus a short delay, since this fires on the raw
     USB "add" uevent, before the device is fully (re)enumerated - racing
     pcscd's restart against that enumeration caused it to come back up
     seeing 0 readers. (This is also why a *manual* restart run a few
     seconds later always looked like it "worked".)
  2. Restarts pcscd (a `reload`/`--hotplug` signal was tried first but
     proved unreliable at picking up a reinserted reader; only a full
     restart worked reliably in testing), then waits briefly again.
  3. Runs `gpgconf --kill scdaemon` for every logged-in user, since
     scdaemon keeps a stale PC/SC session open to the old reader and
     won't reconnect on its own.

These require `sudo` and are only installed on Linux; the hook runs
automatically whenever the `yubikey` module is applied via
`install/apply.sh`.

## Git

The git module keeps repo-safe shared defaults in `~/.gitconfig` and writes personal identity data to:

```text
~/.config/git/local.inc
```

That local file is generated by the wizard/apply flow, so your name, email, and signing key stay out of the repo.

Shared defaults include:

- `main` as the default branch
- `fetch.prune = true`
- `pull.ff = only`
- `push.autoSetupRemote = true`
- `rebase.autoStash = true`
- `rerere.enabled = true`
- `merge.conflictstyle = zdiff3`
- a small set of aliases like `git st`, `git sw`, `git co`, and `git lg`

## Zellij

The Zellij module keeps your `config.kdl` in the repo and makes session serialization explicit.

It also sets `ide` as the default layout, with tabs for:

- `NVIM`
- `Lovely Assistant`
- `Terminal`
- `Docker`

Included helpers:

- `zellij-fix-cache` backs up and clears stale session-manager plugin cache
- `zellij-import-legacy-sessions` copies legacy session metadata from an older Zellij cache version into the current cache contract

Useful recovery flow for your current machine:

1. `zellij-fix-cache`
2. `zellij-import-legacy-sessions`
3. `zellij list-sessions`
4. `zellij attach <session-name>`

## Neovim

The Neovim module keeps only the portable config in `~/.config/nvim`, including:

- `init.lua`
- plugin specs
- `lazy-lock.json`

It does **not** store runtime state from:

- `~/.local/share/nvim`
- `~/.local/state/nvim`
- `~/.cache/nvim`

On apply, if `nvim` is installed, the installer bootstraps:

- lazy.nvim plugins via `Lazy! sync`
- Mason tools via `MasonToolsInstallSync`

Telescope defaults are tuned to:

- show hidden dotfiles
- include files hidden by VCS ignore rules like `.gitignore` and `.git/info/exclude`
- still suppress common noisy paths like `__pycache__`, `.venv`, `node_modules`, `dist`, `build`, and `target`

Extra Neovim keybindings:

- `<leader>pm` opens Mason
- `<leader>pM` installs configured Mason tools
- `<leader>ff` finds files, including dotfiles and VCS-ignored files
- `<leader>fg` live-greps with the same hidden-file behavior
- `<leader>fm` searches tracked git files only

## Copilot

The copilot module is intentionally lightweight. It does **not** store local Copilot auth or state from:

- `~/.config/github-copilot`

It installs small CLI helpers in `~/.local/bin`:

- `copilot-here` runs Copilot in the current directory
- `copilot-project` runs Copilot from the current git repo root when possible

The default Zellij `ide` layout uses `copilot-project` for the `Lovely Assistant` tab.
